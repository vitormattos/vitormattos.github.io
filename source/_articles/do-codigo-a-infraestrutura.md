Publicar o código-fonte é um passo importante, mas não é suficiente para tornar um projeto de software sustentável.

Software livre se torna infraestrutura útil quando as pessoas conseguem compreendê-lo, implantá-lo, mantê-lo, contribuir com ele e confiar que o projeto continuará evoluindo. Isso exige um trabalho que é fácil subestimar: revisar contribuições, documentar decisões, corrigir regressões, organizar lançamentos, apoiar usuários, discutir arquitetura, construir comunidade e encontrar formas de financiar a manutenção sem comprometer a liberdade do software.

Passei boa parte da minha vida profissional trabalhando com PHP, Linux e software livre. Nesse período, vi o mesmo padrão se repetir: a implementação técnica importa, mas o valor de longo prazo de um projeto depende tanto das estruturas ao redor do código quanto do próprio código.

Isso fica particularmente evidente em projetos dos quais organizações passam a depender. Quando um software entra na operação cotidiana, manutenção deixa de ser uma atividade opcional. Compatibilidade, segurança, caminhos de migração, documentação e governança passam a fazer parte do produto, mesmo quando não aparecem como uma funcionalidade ou um pull request específico.

A comunidade também muda a natureza de um projeto. Um repositório público sem participação ainda pode ser útil, mas é muito diferente de um projeto em que usuários relatam problemas, contribuidores propõem mudanças, mantenedores revisam contribuições e decisões são discutidas de forma aberta. O código é o artefato mais visível, mas é a colaboração ao redor dele que permite que o projeto permaneça vivo.

Sustentabilidade importa pelo mesmo motivo. Software livre não significa que desenvolvimento e manutenção não tenham custo. Projetos precisam de pessoas com tempo para revisar issues, desenhar soluções, escrever documentação, responder a problemas de segurança e planejar o trabalho futuro. Construir modelos de negócio e apoio institucional ao redor desse trabalho não contradiz a liberdade do software; em muitos casos, é justamente o que permite que o projeto continue independente e útil ao longo do tempo.

Este site vai documentar parte desse trabalho: decisões técnicas, palestras, projetos, pesquisa, atuação em comunidades e aprendizados de manutenção de software livre em ambientes reais. A intenção não é apresentar código de forma isolada, mas tornar visíveis a engenharia, a colaboração e a manutenção de longo prazo que transformam código em infraestrutura.
