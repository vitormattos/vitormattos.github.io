# Presentations

This directory is the presentation archive independent of Jigsaw and independent of any external presentation provider.

## Native Reveal.js presentations

Create `presentations/<slug>/<locale>.md` and a matching talk record in `source/_talksEn/` or `source/_talks/` with `presentation.type: reveal` and `presentation.source: presentations/<slug>/<locale>.md`.

Reveal Markdown supports horizontal slides separated by `---`, vertical slides by `--`, speaker notes with `Notes:`, fragments through HTML classes, code blocks, backgrounds through section attributes, math/diagram plugins when enabled by the site renderer, overview, scroll view and fullscreen. Keep presentation content free of Blade/Jigsaw syntax so it remains portable.

A minimal deck:

```markdown
<!-- SPDX-FileCopyrightText: 2026 Vitor Mattos -->
<!-- SPDX-License-Identifier: CC-BY-SA-4.0 -->

# Title

Opening slide.

---

## Second slide

- First point
- Second point <!-- .element: class="fragment" -->

Notes:
Speaker notes live here.
```

## PDF and LaTeX presentations

PDF is a first-class presentation format. This is useful for academic presentations authored in LaTeX or for any deck that does not originate in Slides.com or SlideShare.

Keep the generated PDF under the presentation archive, for example:

```text
presentations/empirical-software-engineering/
├── slides.pdf
└── source/
    ├── main.tex
    └── references.bib
```

Create a normal talk record in `source/_talks/` or `source/_talksEn/` and point the presentation to the local PDF:

```yaml
presentation:
  type: pdf
  url: /presentations/empirical-software-engineering/slides.pdf
```

The provider-independent editorial metadata belongs in `data/talks.php`. A talk may have zero or many appearances and resources:

```php
'empirical-software-engineering' => [
    'resources' => [
        [
            'type' => 'pdf',
            'label' => 'Slides (PDF)',
            'href' => '/presentations/empirical-software-engineering/slides.pdf',
        ],
        [
            'type' => 'source',
            'label' => 'LaTeX source',
            'href' => 'https://github.com/example/repository',
        ],
    ],
    'appearances' => [
        [
            'event' => 'Academic seminar',
            'date' => '2026-09-17',
            'venue' => 'University name',
            'city' => 'City',
            'country' => 'BR',
            'mode' => 'hybrid',
            'href' => 'https://example.edu/event',
        ],
    ],
],
```

Use ISO `YYYY-MM-DD` dates, ISO 3166-1 alpha-2 country codes and one of `in-person`, `online` or `hybrid` for `mode`. `href` accepts either an absolute URL or a root-relative path served by this site. CFP pages, official agendas and other provenance belong in `sources`; slides, PDFs, videos, repositories and supporting material belong in `resources`.

The same talk can be presented many times and can point to different slide versions. Put resources that apply only to one occurrence inside that appearance's `resources` array; put reusable resources at talk level.

## Slides.com archive

`presentations/slides.com/<deck-id>/` is generated by `scripts/sync-slides.php`. Never edit generated files manually. The synchronizer only owns files prefixed `slides-com-` in the Jigsaw talk collections and this `slides.com` archive; it must not modify native presentations or `data/talks.php`.

The read-only API synchronization archives public deck HTML, CSS and metadata. PDF and ZIP export creation is intentionally not part of the read-only workflow because Slides.com requires a read-write API key for those operations.
